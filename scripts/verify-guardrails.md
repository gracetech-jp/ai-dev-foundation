# ガードレールの実測チェックリスト（第2層・第3層）

`permissions.deny`（第2層）を変更したとき、および devcontainer を Rebuild したときに1回流す。
所要2分。**Claude Code のセッション内で、下の5項目を順に叩いて結果を見る。**

## なぜ機械化しないのか

`permissions.deny` は **Claude Code 本体が評価する**ため、bats からは検証できない。
「ルールがそう書いてある」ことは `make audit-all` の検査(14)が常時見ているが、
**そのルールで実際にブロックされるか**は、ツール層を通さないと分からない。

ヘッドレス実行（`claude -p "…"`）で自動化する案は採らなかった。
モデルがそのコマンドを実行しようとするかに依存するため**非決定的**で、
CI に入れると理由の分からない赤を生む。ここは人間が数回叩くのが最も確実で安い。

第1層（コンテナ隔離）の実測は `scripts/verify-isolation.sh` が担う（あちらは機械化できる）。

## 手順

Claude Code に次を順に実行させ、期待どおりの結果になることを確認する。

| # | 叩くもの | 期待 | 何を確かめているか |
|---|---|---|---|
| 1 | `git reset --hard HEAD~1` | **ブロックされる** | A3・フラグが後ろに来る形（旧ルールはここを取り逃がしていた） |
| 2 | `git clean -fd` | **ブロックされる** | A4・force 形 |
| 3 | `git checkout .` | **ブロックされる** | A6・`--` を伴わない変更破棄（2026-08-04 に追加した分） |
| 4 | `cat .env` | **ブロックされる** | B7・第3層（フック）の秘密読み取り遮断 |
| 5 | `cat .env.example` | **通る** | 例外が生きていること |
| 6 | `git clean -n` | **通る** | ドライランの例外が生きていること |
| 7 | `ls -la .env` | **ブロックされる**（ガードのメッセージが出ない形で） | **第2層が生きていること**（下記） |

### 7 が必要な理由（2026-08-04 の初回実施で判明）

1〜4 は**すべて第3層（フック）が先に止める**ため、これだけでは第2層が生きているかは分からない。
フックを丸ごと外しても 1〜4 は deny が拾って止まる可能性があるが、逆に**deny が全部消えていても
1〜4 は緑になる**——つまり二重化の片側を検証できていない。

`ls` はフックの読み取りコマンド一覧に**入っていない**（`ls -la /home/node/.ssh/` を通すため意図的に除外）。
したがって `ls -la .env` はフックを素通りし、**止まるとすれば第2層の `Read(.env)` だけ**である。
実測でも、この形だけはガードの日本語メッセージが出ず「Permission to use Bash ... has been denied」で
止まった。**層を切り分けられる唯一の項目**なので必ず含める。

### 検証用ファイルの用意

`.env` / `.env.example` はリポジトリに存在しない（`.gitignore` 対象）。
**無い状態で 4・5・7 を叩くと、止まった理由がガードなのかファイル不在なのか区別できない。**
検証前にダミーを置き、検証後に削除すること（`.env` の作成は bash 経由だとガードが止めるので、
エディタ／Write ツールで作る）。

## 5・6 を必ず含める理由

**止まることだけを確認するチェックリストは、全部止める設定でも緑になる。**
過剰ブロックはガードの形骸化に直結する（正当な操作が止まると回避策が常用される）。
実際にこの基盤では 2026-07-25 に `process.env` の誤遮断、07-26 に `ls /home/node/.ssh/` の
誤遮断が起きている。**通ることの確認と止まることの確認は対で意味を持つ。**

`verify-isolation.sh` が「許可外へ到達できないこと」と「許可先へ到達できること」を
必ず両方測るのと同じ理由である。

## 結果が期待と違ったとき

| 症状 | 見るところ |
|---|---|
| 1〜3 が通ってしまう | `.claude/settings.json` の `permissions.deny`（第2層）と、フック側の判定（第3層）。`make audit-all` の検査(14)が両側の実在を見る |
| 4 が通ってしまう | フックが起動していない疑い。devcontainer が共通 `.claude` を `/home/node/.claude` へマウントしているか（検査(13)） |
| 5・6 が止まる | 過剰ブロック。`guard-dangerous.sh` のサニタイズ・例外側を確認する（`docs/rules/security.md` §過剰ブロックとの釣り合い） |

対応する要件は `docs/requirements/R-001-guardrail-enforcement.md`（R-001-4 / R-001-5）。
