# Tier 分類（S / A / B / C）— 共通

要件・タスク・変更(PR)に **Tier** を付与し、要件検証の厳格度をTierに比例させる（予防コストをリスクに見合わせる）。
この分類はサービス非依存の**枠組み**であり、特定の技術・ドメイン語を前提にしない。
「何が機微か」の具体は各サービスが `SERVICE.md` / `docs/requirements/` に定義する。

> Tierは下流の全ゲート（要件資産の要否・adversarialテスト必須・未カバーゼロゲート・CODEOWNERSレビュー等）を
> 決める。ゆえにTierを低く申告すれば保護が丸ごと蒸発しうる。これを防ぐため、Tierは**人間が批准する
> フィールド**とし（自己申告を信頼しない）、さらに機微コードへの変更を**コード実態からも裏取り**する
> （下記「Tier付与の裏取り」）。

---

## 分類軸（4軸・最大値方式）

Tier は次の4軸それぞれの水準のうち**最も高いもの**に合わせる（1軸でも「高」なら S）。
各軸は抽象水準で定義する（固有の技術・ドメイン語を用いない）。

| 軸 | 高（S相当） | 中〜高（A相当） | 中（B相当） | 低（C相当） |
|---|---|---|---|---|
| 複雑度 | — | 複数モジュール横断・非自明な制御 | 単一モジュール内 | 些末 |
| 影響範囲 | システム全体の権限境界・信頼境界に及ぶ | 外部公開インターフェース・永続データスキーマに及ぶ | 局所的 | ドキュメント・内部ツールのみ |
| 不可逆性 | 取り返しのつかない状態変更（資産（資金・データ等）の確定的な移動・破壊） | 巻き戻しに手当てを要する | 可逆 | 可逆 |
| セキュリティ影響 | 認証・認可、機微データの取扱い、資産の移動や確定に関わる | 認可の内側の業務データを操作する | 実質なし | なし |

## 各Tierの定義（要約）

- **S**：4軸のいずれかが「高」。取り返しがつかない／信頼境界・機微資産に触れる。
- **A**：最高が「中〜高」。外部公開・永続データ・複数モジュールに影響。
- **B**：最高が「中」。単一モジュール内・可逆。
- **C**：すべて「低」。ドキュメント・表示・内部ツール。

## Tier別 要件検証の厳格度（対応表）

この表が下流ゲートの厳格度を規定する。各ゲートの具体的な実装（要件資産・スクリプト・CIジョブ）は
本ルール群の関連ファイルで定義する。

| 検証項目 | S | A | B | C |
|---|:--:|:--:|:--:|:--:|
| ID付き永続要件を持つ | 必須 | 必須 | 推奨 | 任意 |
| 受け入れ基準の明記 | 必須 | 必須 | 必須 | 任意 |
| negative space（起きてはいけないこと）の明記 | 必須 | 必須 | 任意 | 任意 |
| adversarial テストの存在 | 必須 | 必須 | 任意 | 不要 |
| 要件↔テスト紐づけの**人間批准** | 必須 | 必須 | 任意 | 任意 |
| 批准後のテスト改変検知（内容ハッシュ照合） | 必須 | 必須 | 対象外 | 対象外 |
| 未カバー要件ゼロゲート | 対象 | 対象 | 対象（ベースライン猶予可） | 対象外 |
| 未カバーのベースライン免除 | 不可 | 不可 | 可 | 可 |
| CODEOWNERS による人間レビュー | 必須 | 必須 | 任意 | 任意 |
| 要件パスの直push禁止（MVP例外でも） | 全Tier共通で常に必須 | | | |

## Tier 付与の裏取り（自己申告を信頼しない）

- **人間批准**：Tier は要件の front-matter に置く human-ratified フィールド。要件ディレクトリは
  機械的に書き込み拒否されるため（LLMは変更不能）、Tierの昇降は人間の commit でのみ成立する。
- **コード実態からの裏取り**：申告Tierの過小評価（デスカレーション）を防ぐため、機微コードへの変更を
  パス／シンボルの**トリップワイヤ**でも検査する。S相当の変更にS要件が対応していなければゲートを赤にする。
  機微パターンの実体は各サービスが `SERVICE.md` に定義する（**共通リポは既定値を持たない**）。
