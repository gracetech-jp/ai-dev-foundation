# コードスタイルガイドライン（共通・言語非依存）

本ファイルは全サービス共通の原則のみを扱う。**言語・フレームワーク固有の具体**（各言語の命名ケース、リンタ・型チェッカ名、フレームワークのファイル規約、モジュールの標準ファイル構成）は各サービスの `SERVICE.md` に定義する。

## ファイル共通
- インデント：TAB
- 文字コード：UTF-8
- 改行コード：LF（Windowsでも必ずLF）
- ファイル末尾：改行あり
- ファイルはドメイン（カテゴリ）単位でまとめる。可読性が損なわれない限り、行数だけを理由に分割しない
- マジックナンバーは定数として定義する
- コメントは「何をしているか」ではなく「なぜそうしているか」を書く

## 命名
- 命名は対象言語・エコシステムの慣習に従い、プロジェクト内で一貫させる
- 変数・関数・クラス・定数・ファイル名・DBカラムのそれぞれに規則を定め、混在させない
- 具体的な命名ケースの割り当て（camelCase / snake_case / PascalCase / kebab-case 等）と例外規定は、対象言語ごとに `SERVICE.md` へ表で定義する

## 型
- 静的型付けを持つ言語では、関数の引数・戻り値に必ず型を付ける
- 型安全を損なう回避（型の握りつぶし・過度なキャスト）は最小限にし、やむを得ない場合は理由をコメントに残す

## リンタ・フォーマッタ
- 構文・import順・型・セキュリティは、リンタ／型チェッカで機械強制する（人手のレビューだけに頼らない）
- 使用するツールと設定ファイルの場所は `SERVICE.md` に定義し、CI のブロッキングゲートに含める

## モジュール構成
- ドメイン単位でモジュールを分割する（モジュラーモノリス原則）
- モジュール内の標準ファイル構成、および許容される逸脱（例：呼び出し元別のルーター分割、モデルを持たないインフラ的モジュール）は `SERVICE.md` に定義する
