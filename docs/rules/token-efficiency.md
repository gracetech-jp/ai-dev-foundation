# トークン効率化ガイドライン

トークンの浪費を避けつつ、**品質保証は一切削らない**ことが原則。
削ってよいのは「読み込む範囲」と「説明の冗長さ」だけで、テスト・レビュー・整合性監査は全Tierで必須。

---

## 1. 調査（読み込み）の効率化
- まず該当箇所を**特定してから**、必要な範囲のみを読む（`grep`・ファイル検索で当たりを付ける）。
- ファイル全体を読む前に、対象の関数・セクションだけを部分読みできないか検討する。
- **一度読んだ内容は読み直さない**。会話内で既に得た情報を再取得しない。
- 広範な探索が必要なときは探索専用エージェントに任せ、結論だけ受け取る（全文をコンテキストに載せない）。

## 2. 編集（出力）の効率化
- **部分差分（該当行のみの置換）を優先**し、変更のないコードを再掲しない。
- ファイル全体の書き直しは、新規作成・全面刷新のときに限る。
- 説明は要点のみ。同じ内容を別の言い回しで繰り返さない。

## 3. 説明・応答の効率化
- 前置き・後置きの定型文を省き、結論から書く。
- すでに合意済みの前提・決定を再説明しない。
- 選択肢の全列挙より、推奨案を1つ提示する（判断が要る場合のみ選択肢を出す）。

---

## 削ってはいけないもの（MUST）
- 既存テストの実行・新規テストの作成（詳細: `docs/rules/testing.md`）
- 整合性監査（詳細: `docs/rules/consistency.md`）
- セキュリティ・コードスタイルの遵守

> 「トークン節約」を口実に品質ゲートを飛ばさない。効率化の対象はあくまで読み込み範囲と説明の冗長さのみ。
