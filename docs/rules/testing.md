# テストガイドライン（共通・言語非依存）

本ファイルは全サービス共通の原則のみを扱う。**フレームワーク名・テスト用DB・CIジョブ名・現状のカバレッジ数値・モック対象の外部サービス**など、スタック固有の具体は各サービスの `SERVICE.md` に定義する。

## 基本ルール
- 新機能の実装時は必ずテストを同時に作成する
- バグ修正時は再現テストを先に書いてから修正する
- テストなしのコードはマージ不可

## カバレッジ目標
| 対象 | 目標 |
|---|---|
| ビジネスロジック | 80%以上 |
| APIエンドポイント | 100%（正常系・異常系） |
| ユーティリティ関数 | 100% |

- 上記は目標値。これとは別に「現状値からの低下を防ぐフロア」をCIで機械強制し、テストを追加しながら段階的に引き上げる。フロアの現在値・実行コマンド・CIジョブ名は `SERVICE.md` に定義する

## テスト名
- 正常系・異常系が名前から判別でき、入力条件と期待結果が読み取れる命名にする
  （例：「正常系: 〜が存在する場合、〜を返す」「異常系: 〜が存在しない場合、404を返す」）

## 方針
- 単体テストを優先し、結合テストは最小限に抑える
- テストは独立して実行可能にする（他テストの結果に依存しない）
- モックは外部依存（DB・外部API）に限定し、内部ロジックはモックしない
- テストデータはファクトリー関数で生成し、ハードコードしない
- 使用するテストフレームワーク・テスト用DB・モック対象の外部サービスは `SERVICE.md` に定義する
