# テストガイドライン

## 基本ルール
- 新機能の実装時は必ずテストを同時に作成する
- バグ修正時は再現テストを先に書いてから修正する
- テストなしのコードはマージ不可

## カバレッジ目標
| 対象 | 目標 |
|---|---|
| ビジネスロジック | 80%以上 |
| APIエンドポイント | 100%（正常系・異常系） |
| ユーティリティ関数 | 100% |

## 命名規則
test('正常系: ユーザーIDが存在する場合、ユーザー情報を返す', ...)

test('異常系: ユーザーIDが存在しない場合、404エラーを返す', ...)

## 方針
- 単体テストを優先し、結合テストは最小限に抑える
- テストは独立して実行可能にする（他テストの結果に依存しない）
- モックは外部依存（DB・API）に限定し、内部ロジックはモックしない
- テストデータはファクトリー関数で生成し、ハードコードしない
