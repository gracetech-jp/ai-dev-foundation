# 要件（この基盤リポジトリ自身のガバナンス要件）

このディレクトリは `ai-dev-foundation` **自身**の一次要件を、永続資産として置く。
基盤はアプリを持たないが、「基盤が保証すると約束したガバナンス（破壊的操作の機械遮断など）」を
要件化し、シェルテスト（`tests/*.bats`）で検証することで、**基盤が自ルールを dogfood** する。

- 形式・採番・要件の編集と有効化: `docs/rules/requirements.md`
- Tier の定義: `docs/rules/tiers.md`
- LLM も要件を直接生成・編集できる（2026-07-24 批准レス化・ADR-008）。ただし既存要件の
  意味変更・緩和・削除はユーザーの了解を得てから行い、理由をコミットに残す。

## ディレクトリ構成

```
docs/requirements/
├── README.md                        # このファイル（要件一覧と運用）
├── R-001-guardrail-enforcement.md   # 破壊的操作・秘密読取の事故防止（第2層・第3層。Tier S）
├── R-002-common-owned-lockdown.md   # 共通所有ファイルの編集・複製の封鎖（Tier S）
└── R-003-egress-allowlist.md        # 外向き通信の許可宛先の限定（Tier S）
```

`.tier-tripwire-none`（機微面なしの明示宣言）は基盤には置かない。基盤の機微面は
**配布するガードレール自身**であり、`Makefile` の `TIER_TRIPWIRE_PATHS` に明示している
（空宣言でスキップすると ADR-008「維持したもの」と矛盾するため。2026-07-25 是正）。
