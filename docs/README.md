# docs/ — 共通ルール・要件・意思決定の置き場

このリポジトリのドキュメントは4種類に分かれている。**種別ごとに正本が1つ**で、混ぜない。

## ディレクトリ構成

```
docs/
├── README.md        # このファイル（種別の地図）
├── rules/           # 全プロジェクト共通のルール（正本。各プロジェクトは参照する）
├── requirements/    # 基盤自身の要件（永続資産・一意ID。批准レス運用: ADR-008）
├── decisions/       # ADR（基盤の意思決定記録。なぜそう決めたか）
├── service-rules/   # 基盤自身に固有のルール（共通ルールに混ぜないもの）
└── audit/           # 棚卸し・監査の記録（日付入りのスナップショット。事後に書き換えない）
```

## 種別の使い分け

| 書きたいこと | 置き場 |
|---|---|
| 全プロジェクトが従う原則・手順 | `rules/` |
| 「何を満たすべきか」（一意ID・negative space・Tier） | `requirements/` |
| 「なぜその方式を選んだか」「何を採らなかったか」 | `decisions/` |
| この基盤リポだけの具体手順 | `service-rules/` |
| ある時点で調べた結果 | `audit/` |

- `rules/` は**全プロジェクトが読む共通正本**。スタック固有名（特定の言語・FW・ORM・コマンド）を書かない。
- `requirements/` の ID は再利用しない。既存要件の意味変更・削除はユーザーの了解が要る
  （テストを緑にする目的で要件を動かすのは禁止）。
- `decisions/` と `audit/` は**当時の記録**。後から実装が変わっても本文は書き換えず、
  ステータス行や追記で「置換済み（→ NNN）」を示す。

## 所在の書き方

「何がどこにあるか」は各ディレクトリの README にツリーで書く。ルール文書側に構成を列挙しない
（理由と規約: `rules/repo-layout.md`「所在の管理は各階層の README が正本」）。
