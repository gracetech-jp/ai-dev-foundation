# ADR-003: 共通ルールは基盤リポを正とし、改善は逆輸入で全サービスへ配る

## 日付
2026-07-11

## ステータス
採用済み

## 背景
共通ルール（`docs/rules/` 等）を各サービスへコピー配布すると、あるサービスでルールを改善しても
そのサービス内に閉じてしまい、他サービスへ伝播しない（フォークの分岐）。一方で自由に相互マージすると、
サービス固有物（特定言語/FW/ORM/ドメイン識別子）が共通ルールに逆流して中立性が壊れる。

## 決定
基盤リポ `ai-dev-foundation` を共通ルールの唯一の正本とする。サービス側で共通ルールを改善したら、
`.backport-manifest` に列挙した**共通所有ファイルだけ**を `scripts/backport-to-common.sh` で基盤へ還流し、
基盤から再配布する。サービス固有は `SERVICE.md`・`docs/service-rules/` に分離し、還流対象に含めない。

## 理由
- 「正本は1つ・改善は還流」で、フォーク分岐を避けつつ全サービスへ改善を行き渡らせられる。
- 機械同期は中身を抽象化しないため、**共通所有ファイルには最初からサービス固有物を書かない**規律を
  マニフェスト（allowlist 方式）で強制できる。新規ファイルは既定で還流しない（`--allow-new` が合図）。
- dirty な共通リポには適用せず、上書き分は `.backport-backup-*/` に退避＝事故を機械的に防ぐ。

## 注意事項
- `templates/` 由来として配布される骨格（`.claude/`・`.devcontainer/`・`.github/workflows/`・`Makefile`・
  監査雛形・`.editorconfig` 等）はサービス側とパスが 1:1 対応しないため機械還流できず、**手動同期**とする
  （`.backport-manifest` 注1／`docs/rules/backport.md`）。
- マニフェスト自身は還流対象に含めない（リポごとのローカル設定のため）。

## 結果
共通ルールの改善が一方向のコピーで死蔵されず、全サービスへ配れる。中立性はマニフェストの allowlist と
「固有物は分離」の規律で守られる。
