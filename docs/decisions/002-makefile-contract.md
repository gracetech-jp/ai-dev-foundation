# ADR-002: 品質ゲートの入口を Makefile ターゲット契約に統一する

## 日付
2026-07-11

## ステータス
採用済み

## 背景
本基盤は複数サービス（言語・スタックが異なる）へ共通ルールを配布する。品質ゲート（テスト・静的解析・
整合性監査・カバレッジ・依存監査）は「フック・CI・人間」が同じ入口を共有しないと、実行方法がバラつき
「ローカルでは通るが CI で落ちる」「フック未導入で素通り」といった事故が起きる。一方で具体コマンド
（`npm test` / `pytest` 等）はスタック依存であり、共通リポに直接書くと中立性が壊れる。

## 決定
スタックによらず同じ名前の Make ターゲットを規約として定める：
`test` / `lint` / `coverage` / `audit-all` / `audit-deps` / `install-hooks`。
中身は各サービスが自スタックで実装し、共通側は「ターゲット名の契約」だけを持つ。
フック・CI・人間はこの `make <target>` を唯一の入口として共有する。

## 理由
- 入口を1つに固定することで、実行方法の分岐（誰が・どこで・どのコマンドか）を消せる。
- 契約はターゲット名のみ＝スタック非依存。具体コマンドは `Makefile` 本体と `SERVICE.md` に委譲でき、
  共通ルールの中立性（ADR-003 の逆輸入とも整合）を保てる。
- CI は make を呼ぶだけになり、CI YAML から言語固有コマンドを排除できる（devcontainer 実行と併せて）。

## 注意事項
- ターゲットの**存在**は `scripts/audit-consistency.sh` の「make ターゲット契約の検査」で機械強制する。
  ターゲットを増減したら、この監査・`docs/rules/quality-gates.md` §1 の表・雛形 `templates/Makefile` を同時に更新する。
- 雛形の未実装ターゲットは `exit 1`（fail-closed）にし、実装するまで CI を赤にして放置を防ぐ。

## 結果
新規サービスは `make test/lint/coverage/audit-all/audit-deps` を実装すれば、フック・CI・手元の実行が
自動的に揃う。共通リポは具体コマンドを持たずに品質ゲートの枠組みだけを配布・維持できる。
