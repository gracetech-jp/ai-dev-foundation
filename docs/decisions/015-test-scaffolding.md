# ADR-015: テストの雛形とゴールデンデータセットを配布し、「空虚な緑」を検知する

- 日付: 2026-08-03
- ステータス: 採用

## 背景

テスト工程はルール（`docs/rules/testing.md`）とゲート（req-coverage / tier-tripwire / coverage-floor）が揃っているのに、**雛形が 1 つも配布されていない**。`tests/` ディレクトリすら生成されない。

結果として生成直後のプロジェクトで次が起きる。

- `check-requirements-coverage.sh` は `[ -e "$p" ] || continue` で存在しないパスをスキップするため、要件 0 件なら緑
- product-static は `.tier-tripwire-none` が同梱されるため tier-tripwire も正当スキップして緑
- つまり**何も検証していないのに全ゲートが緑**になる

2026-07-24〜25 に基盤自身が同じ状態（空設定 + 機微面なし宣言で緑）になった実績があり、検査(8)が追加されている。同じ穴が配布物側に残っている。

加えて、AI を組み込んだサービスでは応答が非決定的であり、通常の assert では検証できない。この検証手段が現在まったく存在しない。

## 決定

### 1. テストの雛形を配布する

- `tests/` ディレクトリを生成する
- 要件マーカー（`@req:` / `@adversarial:`）付きのサンプルテストを 1 本以上配布する
- adversarial テストの雛形を配布する

生成直後に「テスト 0 件だから緑」にならない状態を作る。

### 2. ゴールデンデータセットを導入する

期待される結果が検証済みの、現実的なシナリオの代表的な集合を作り、回帰の基準とする。

```
tests/golden/
  cases.yaml        入力と、期待される応答の性質
  README.md         更新規約
```

非決定的な出力に対しては、完全一致ではなく**性質**（含むべき情報、含んではならない情報、形式、トーン）で検証する。

### 3. 品質ゲートを設ける

自動テストがゴールデンデータセットに対して精度・根拠性・安全性を測定し、レッドチームが敵対的プロンプトで脆弱性を突き、最後に正式な承認を行う。**承認なくばデプロイなし。**

この承認は ADR-016 の本番リリース承認と同一の地点とする（人間の判断点を増やさない）。

### 4. 空虚な緑を検知する

配布側の `audit-consistency.sh` に、基盤の検査(8)相当を追加する。

- `tests/` が存在しない、または中身が空
- 要件 0 件のまま `.tier-tripwire-none` が置かれている状態が一定期間続く
- `.coverage-floor` が 0 のまま

これらを警告として出す。

## 理由

### 雛形がないゲートは空回りする

ゲートは「対象が存在しない場合にスキップする」設計になっている。これは fail-open であり、ADR-012 で採用した fail-closed の原則に反する。ただしゲート側を fail-closed にすると生成直後に必ず赤になるため、**雛形を配って対象を実在させる**ことで解決する。

### ゴールデンデータセットの根拠

AI エージェント開発の実務では、設計段階でゴールデンデータセットを確立することが標準とされる。実世界のシナリオの代表的な集合に対して専門家が期待結果を検証したものを用意し、ライフサイクル全体を通じて精度・一貫性・回帰性能を評価する基準（ground truth）とする。

評価の構成も定型化している。自動テストがゴールデンデータセットに対して精度・根拠性・安全性を測定し、人間のレビューが判断品質・推論・コンプライアンスを評価し、レッドチームが敵対的プロンプトで脆弱性と安全性のギャップを暴く。最後に品質ゲートで正式な承認を行い、承認がなければデプロイしない。

要件が変わった場合は、設計に戻して仕様を更新し、更新されたゴールデンデータセットに対して再テストしてから再デプロイする、というループになる。

### 「空虚な緑」を仕組みで検知する

基盤自身が一度陥った失敗である。同じ類型の失敗は仕組みに還元する（`CLAUDE.md` の「AI が同じ間違いを繰り返した場合、原因と理由をルールファイルに追記する」の拡張）。

## 注意事項

- product-static の `.tier-tripwire-none` は正当な機能である。廃止せず、「置かれたまま要件が増えない」状態を警告する
- ゴールデンデータセットは AI 応答を持つサービスにのみ必要。`product-static` プロファイルでは不要とし、プロファイル別に配布を分ける
- レッドチームは自動化する。実装したセッションと別セッションの AI に敵対的プロンプトを生成させる（`docs/rules/requirements.md` §6 の adversarial 生成規約と同じ方針）
- `.coverage-floor` の一方向ラチェットは維持する。floor の引き上げは手動のままとする

## 結果

- `profiles/_base/tests/` に最小のサンプルテストとマーカーを配布する
- `profiles/product-web/files/tests/golden/` にゴールデンデータセットの雛形を配布する
- `profiles/_base/scripts/audit-consistency.sh` に空虚な緑の検知を追加する
- 品質ゲートを reusable workflow に組み込む（ADR-011）
- `docs/rules/testing.md` にゴールデンデータセットの運用規約を追加する
