# ADR-008: 要件トレーサビリティの批准レス化（人間批准の仕組みの廃止）

記録日: 2026-07-24 ／ 対象リポ: ai-dev-foundation ／ 状態: 承認済み（大澤将平・2026-07-24）・実装済み

## 背景 — 解決したかった問題

ADR-007 の要件トレーサビリティ基盤は「LLMの自己申告を単独で信頼しない」を核に、複数の**人間批准
ポイント**（要件のLLM編集封鎖・`tests_ratified_by`・`tests_ratified_sha`・Tier の人間批准・
CODEOWNERS レビュー必須化）を置いていた。しかし solo 運用では、これらが**都度「人間の commit /
対応待ち」でワークフローを止める**ボトルネックになり、作業効率を明確に損なっていた
（例: テストを1行整えるだけでハッシュ再批准が必要になる）。

## 決定

**人間の対応待ちを発生させる仕組みだけを廃止し、待ちを発生させない機械ゲートは全て維持する。**
品質担保は「人間レビュー最小化・機械ゲートで質担保」の基本方針に一本化する。

### 廃止したもの（人間批准ポイント）

| 対象 | 実体 |
|---|---|
| 要件のLLM編集封鎖（旧G3） | `settings.json` の `Write/Edit(docs/requirements/**)` deny・`guard-dangerous.sh` の要件書込遮断・SessionStart の封鎖注意文 |
| 要件↔テストの妥当性批准（旧B1） | front-matter `tests_ratified_by` と check スクリプトの必須チェック |
| 批准後のテスト改変検知（旧F1/F3） | front-matter `tests_ratified_sha`・`test_assets`・ハッシュ算出（`--sha`）・再批准要求 |
| Tier の人間批准 | 「Tierは人間批准フィールド」の規定（tiers.md） |
| CODEOWNERS レビュー必須化 | `.github/CODEOWNERS`・`profiles/_base/.github/CODEOWNERS.template`（削除）・監査の CODEOWNERS 検査・git.md のブランチ保護チェックリスト・MVP例外からの要件パス除外 |
| `.req-drafts/` 経由の下書き動線 | extract-requirements スキルは `docs/requirements/` に直接 `status: draft` で作成する運用へ |

### 維持したもの（待ちを発生させない機械ゲート）

- **要件の永続資産化・一意ID**（G1相当）: 要件をタスクごとに再導出させない、という ADR-007 の
  発端の問題への防壁はこれが本体。ファイルとして残る限り、生成ループの外側のアンカーは保たれる。
- **req-coverage**: 未カバー要件（S/A 即赤）・dangling マーカー・G4（negative_space に adversarial 必須）・
  B3（S/A のベースライン免除禁止）。
- **tier-tripwire**: 機微パス/シンボル変更へのS要件要求（コード実態からの裏取り）・機微 test/fixture への
  S要件要求・S4 静的走査。`.tier-tripwire-none` / `.tier-tripwire-allow` の明示宣言ファイル方式も維持
  （「人間 commit」の要求は撤去し、コミットの存在だけを要求）。
- カバレッジ・フロア（一方向ラチェット）・lint ゼロ警告・CI/pre-push の二重化・guard-dangerous の
  破壊的操作/秘密読取遮断（R-001）は本 ADR の対象外（変更なし）。

### 追加した運用規範（機械強制ではなくプロンプト規範）

- **要件を実装の都合で書き換えない**: 既存要件の意味変更・緩和・削除はユーザーの了解を得てから行い、
  理由をコミットに残す（requirements.md §3・CLAUDE.md・SessionStart 注入文に明記）。
  テストを緑にする目的で要件側を動かすことは禁止。

## トレードオフ（認識済みで受け入れたリスク）

- 要件が再びLLMの編集可能範囲に入るため、「実装に合わせて要件を書き換えて緑にする」経路が
  **機械的には**塞がれなくなった。緩和策: ①要件は永続ファイルであり差分がレビュー可能、
  ②上記の運用規範、③G4/B3/tripwire は維持されるため「テストごと消す」「Tierを下げて逃げる」は
  依然として機械検出される。
- adversarial テストの人間レビュー必須（旧§6）も廃止し「別コンテキスト生成の推奨」に緩和した。

## 復活条件

共同開発者が増えた時点（または外部リリースで要件の監査証跡が必要になった時点）で本 ADR を見直し、
CODEOWNERS＋ブランチ保護（サーバ側）を最優先で復活させる。`tests_ratified_*` のハッシュ機構は
git 履歴（ADR-007 時点の実装）から復元できる。
