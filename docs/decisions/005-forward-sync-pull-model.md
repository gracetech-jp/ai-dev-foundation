# ADR-005: 共通→既存サービスの前方配布は pull 型スクリプトで行う

## 日付
2026-07-12

## ステータス
採用済み（双方向ループ前提の記述のみ置換済み（→ 009）。pull 型順輸入自体は現役）

## 背景
ADR-003 は「基盤リポを正とし、改善は逆輸入で還流して基盤から再配布する」と定めたが、
「再配布」の実装は `new-service.sh`（新規作成時のみ）しか無く、**既存サービスへ共通ルールの
改善を届ける手段が欠けていた**。あるサービスの改善を還流しても他の既存サービスに伝播しない＝
双方向ループの片翼が欠落していた。

## 決定
サービス側に配布する pull 型スクリプト `scripts/sync-from-common.sh` で前方配布を行う。
各サービスが自分のタイミングで共通リポから共通所有ファイルを取り込む。

- 対象の解決は**共通リポ側の `.backport-manifest` を正**とする（サービス側ローカル改変で取込範囲が歪まない）。
- **新規ファイルも既定で追加**する（逆輸入の `--allow-new` 要求と非対称）。順方向の新規＝共通リポで
  生まれた新ルールであり、配布がこのツールの目的そのものだから。逆方向は固有物の漏出リスクがあるため
  明示フラグを要求する。
- 安全機構は逆輸入と同型：dry-run 既定・サービス側 dirty で中断（`--force` 回避可）・
  上書き分は `.sync-backup-*/` へ自動退避。コピーは一時ファイル+`mv` のアトミック差し替え
  （取込対象に自分自身が含まれても実行中プロセスを壊さない）。
- スクリプト自身をマニフェストに載せて自己ホスティングする（ツールの改善も還流・取込で伝播）。

## 検討した代替案
- **push 型（基盤から全サービスへ一括配布）**：一括性は高いが、基盤が全サービスのローカルパスの
  名簿を持つ必要があり、受け側の都合（作業中・dirty）を踏みにじるリスクがある。却下。
- **git subtree / 外部テンプレートツール（copier 等）**：機械的には堅いが、既存のマニフェスト
  モデル（ADR-003）を作り直す大工事になる。学習コストも増える。却下。

## 結果
双方向ループが完成する：改善はどのサービスで生まれても `backport-to-common.sh` で共通リポへ還流し、
他の既存サービスは `sync-from-common.sh` で取り込める。運用カデンスは docs/rules/backport.md 参照。
