# docs/decisions/ — ADR（この基盤の意思決定記録）

**なぜその方式を選んだか／何を採らなかったか**を残す。コードや実装からは読み取れない背景が対象。
ここにあるのは**基盤リポ `ai-dev-foundation` の決定**で、各プロジェクト固有の決定は
そのプロジェクトの `docs/decisions/` に置く。

## ディレクトリ構成

```
docs/decisions/
├── README.md                              # このファイル（一覧と運用ルール）
├── 001-devcontainer.md                    # 開発環境を devcontainer で統一する
├── 002-makefile-contract.md               # 品質ゲートの入口を Makefile ターゲット契約にする
├── 003-backport-model.md                  # 共通ルールの逆輸入モデル（置換済み → 009・010）
├── 004-claude-guardrails-distribution.md  # Claude Code ガードレールの選択的追跡と配布
├── 005-forward-sync-pull-model.md         # 順輸入は pull 型スクリプトで行う（失効 → 010）
├── 006-adr-profile-based-bootstrap.md     # 新規プロジェクト生成のプロファイル合成方式
├── 007-requirements-traceability.md       # 要件トレーサビリティ基盤（人間批准あり）
├── 008-ratification-less-traceability.md  # 要件の批准レス化（人間批准の仕組みを排除）
├── 009-one-way-distribution.md            # 逆輸入の廃止と共通所有ファイルの機械封鎖
└── 010-reference-only-common-assets.md    # 順輸入の廃止。共通資産は配布せず参照する
```

## 現役 / 置換済み

| 現役 | 001・002・004（CODEOWNERS 部分を除く）・006・007（批准系を除く）・008・009（ロックの決定）・010 |
|---|---|
| **置換済み・失効** | **003**（→ 009・010）・**005**（→ 010）・**007/004 の一部**（→ 008） |

配布モデルは 003 →（一方通行化）→ 009 →（配布そのものを廃止）→ 010 と変遷した。
現在の到達点は **010（参照方式）**で、運用上の正は `docs/rules/common-assets.md`。

## 運用ルール

- 1決定 = 1ファイル。連番＋短いスラッグで命名する：`NNN-短い題名.md`。
- **連番は削除・再利用しない**（履歴として残す）。却下・置換されても消さず、ステータスを更新する。
- 新しい決定が過去を覆す場合は、古い方のステータスを `置換済み（→ NNN）` にし、
  新しい方に背景と「置き換えた ADR」を書く。**過去の本文は書き換えない**（当時の記録だから）。
- 実装が変わって過去 ADR の記述が現状と食い違うときは、本文ではなく**注記の追加**で示す。
- 迷ったら書く：後から「なぜこうなっているのか」を訊かれる決定は ADR 化する価値がある。
