# Architecture Decision Records (ADR)

このディレクトリには、このサービスの**アーキテクチャ上の意思決定**を記録する。
「なぜこの技術・構成・方式を選んだか」を後から辿れるようにするのが目的（コードからは読み取れない背景）。

## ディレクトリ構成

```
docs/decisions/
├── README.md         # このファイル（運用ルール）
└── 000-template.md   # ADR の雛形（コピーして使う）
```

## 運用ルール

- 1決定 = 1ファイル。連番＋短いスラッグで命名する：`NNN-短い題名.md`（例：`001-use-postgres.md`）。
- 連番は削除・再利用しない（履歴として残す）。却下・置換されても消さず、ステータスを更新する。
- 新しい決定が過去の決定を覆す場合は、古い方の「ステータス」を `置換済み（→ 00X）` にし、新しい方に背景を書く。
- 雛形は `000-template.md` をコピーして使う。
- 迷ったら書く：後から「なぜこうなっているのか」を訊かれる決定は ADR 化する価値がある。

## ステータスの値

`提案中` / `採用済み` / `却下` / `置換済み（→ NNN）` / `非推奨`
